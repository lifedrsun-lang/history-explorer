## 구현

- 브라우저의 전체 학생 컬렉션 조회/비밀번호 비교를 서버 로그인 API로 이전했다. 이름 검색 결과는 계정 선택에 필요한 필드만 반환한다. 로그인 응답은 허용 목록에 있는 본인 프로필만 반환한다.
- 기존 `selectedStudent` 로컬 저장 데이터를 지우며, 인증은 임의의 학생 JSON 대신 서버 세션을 이용한다. 토큰 원문은 HttpOnly/SameSite=Strict 쿠키에만 전달하고 DB에는 SHA-256 해시를 저장한다. HTTPS에서는 Secure와 `__Host-` 접두어를 사용한다.
- 세션 유효기간은 8시간. 학생 상태와 기존 자격정보의 버전을 매번 서버에서 다시 확인한다. 로그아웃, 자격정보 변경, 만료 후 세션 사용을 거부한다.
- 학생 과제 조회·사진 제출, 복습 조회·완료, 코인 교환 API에 서버 세션 검사를 연결했다. 요청 본문의 타 학생 ID와 레거시 비밀번호만으로는 인증할 수 없다.
- 교사 미리보기는 별도 쿠키와 30분 세션을 사용하며 매 요청마다 승인된 교사 토큰을 확인한다. 쓰기와 학생 사진 인증을 허용하지 않는다.
- 사진은 기존 학습 로그인과 별도로 개인 확인코드를 요구한다. 교사가 학생/보호자의 신원을 확인한 후 개인별로 전달하는 운영 절차를 표시한다. 코드는 발급할 때만 표시하고 서버에는 해시만 저장한다. 유효기간은 180일이다. 재발급·해제 시 이전 코드와 인증된 사진 세션은 무효가 된다.
- 사진 코드가 있어도 기존 앨범의 역사적 명부, 분기 이력, 동의, 공개 여부, 한국시간 공개기간 검사는 모두 적용한다.
- 서버 교사 권한은 `STUDENT_AUTH_TEACHER_UIDS`에 있는 기존 계정과 비밀번호 로그인 provider를 모두 검사한다. 환경 설정이 없거나 미승인 계정이면 거부한다.
- 로그인·코드 입력의 횟수 제한을 서버 DB 함수로 관리한다. DB 실패 시 우회 허용하지 않는다.
- 관리자 `/teacher/student-security`에서 학생 사진 확인코드 발급·해제를 제공하며, 사진 관리 화면에서 연결한다.

## DB 변경 준비 / 실행 결과

- `supabase/migrations/20261017010000_student_server_sessions.sql`: 서버 세션, 사진 코드, 시도 횟수 전용 새 테이블 3개와 횟수 제한/만료 정리 함수.
- 기존 테이블 변경 없음. 신규 테이블의 RLS를 켜고 `public`, `anon`, `authenticated` 접근과 함수 실행 권한을 회수하며 `service_role`만 허용하도록 작성했다.
- 실제 DB 읽기 전용 확인에서 새 세션/사진 코드 테이블은 **없음**으로 조회됐다.
- 마이그레이션 요청은 `Invalid or expired requestState` 오류로 실행되지 않았다. 재확인 후 재시도와 트랜잭션 SQL 대안도 같은 연결 오류를 반환했다. **DB 적용 완료로 취급하지 않는다.**
- 분기 앨범 연결 학생 수는 조회 시 0명이었다. 학생 사진 공개 환경변수를 켜지 않았다.

- 실제 교사 로그인 상태의 학생 미리보기·확인코드 운영, 실제 학생 계정의 로그인·새로고침·과제·복습·보상 전체 검증.
