# School entry codes: first rollout
Scope: Saesol, Haneulbit, Sau. Sau remains paused in 2026-Q4. Deunghyeon is excluded from guardian activation until its separate student entry setup is validated.
Teacher school card: reveal/hide and change per-school student codes and a shared guardian code. The requested value must be entered in the authenticated teacher UI, never committed to source. Guardian access still requires a separately issued child code; common-code changes revoke all existing guardian sessions.
Server prerequisites (do not enable or deploy to production until verified): SCHOOL_ENTRY_CODES_ENABLED=true, SCHOOL_ENTRY_CODES_KEY (32 random bytes encoded as 64 hex chars), SCHOOL_ENTRY_TEACHER_UIDS (or existing GUARDIAN_TEACHER_UIDS), GUARDIAN_CLASSROOM_ENABLED and GUARDIAN_TEACHER_UIDS. Store keys in server-only environment; verify Firestore client read/write denial for school_entry_codes, school_entry_code_limits and all guardian collections. Existing legacy student code is used only until an override is configured; do not advertise existing legacy code system as secure. This change does not secure the existing client roster/localStorage student flow. Test with synthetic students and a separate test database before enabling.
No live values, calendar events, student records, or production configuration changed by this commit.
