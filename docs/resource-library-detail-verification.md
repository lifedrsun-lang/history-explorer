# 수업자료 공통 상세보기 변경 및 검증

## 변경 범위

- `ResourceLibraryLayout`을 일반 수업자료, 교재 카드, 보드게임, 내 공부자료에서 함께 사용한다.
- PC 목록/상세 영역 비율은 2:1이며 두 영역의 세로 스크롤을 분리한다.
- 모바일은 native dialog 전체화면을 사용한다. 닫기와 Escape로 목록에 복귀하며 포커스와 페이지 스크롤을 복구한다.
- 이전/다음은 즐겨찾기와 필터를 반영한 현재 목록 순서를 따른다. 양 끝에서 이동을 비활성화한다.
- 기존 등록/수정 폼을 공통 컴포넌트로 분리하여 상세 패널에서 사용하고 기존 독립 경로도 유지한다.
- 상세 패널의 수정은 편집한 필드만 갱신한다. 분류·호수·차시·세계문화 시리즈 설정도 패널에서 수정할 수 있다.
- 이름이 있는 카드의 이름 수정은 해당 그룹 전체에 적용하되 기존 `cardKey`를 유지한다. 키가 없는 구형 자료만 기존 파생 키를 저장하여 이름 변경 후 그룹이 분리되지 않게 한다.
- 새 자료 추가는 기존 카드의 키를 그대로 사용한다. 보드게임 메타데이터 편집은 기존 생성일을 덮어쓰지 않는다.
- 기존 스키마에 없는 설명·첨부파일·학년·대상·공개 설정 필드를 새로 만들지 않았다. 해당 화면에서 실제 지원하는 자료 유형, 호수, 차시, 링크, 개인 공부 자료 종류와 보드게임 이미지·업체명만 관리한다.
- 데이터 마이그레이션, 일괄 초기화, 자동 삭제는 수행하지 않았다.

## 검증 방식과 범위

Playwright/Chromium에서 실제 페이지와 실제 공통 컴포넌트를 실행했다. 테스트 중 Firebase Auth/Firestore 모듈만 메모리 대체 모듈로 연결했다. 운영 데이터베이스에 쓰지 않았으며 테스트 설정은 배포 소스에서 제거했다.

PC 1440×1000, 모바일 390×844에서 아래 시나리오를 확인했다. 긴 목록 및 긴 상세 정보, 명명 카드, 교재 카드, 보드게임 메타데이터, 고정 저장 키가 있는 개인 공부자료를 사용했다.

| 확인 사항 | 결과 |
| --- | --- |
| PC 카드 선택 시 페이지 이동 없이 상세 정보 표시 | 통과 |

보존 검증에서는 카드 키, 분류, 호수, 차시, 생성일과 테스트용 설명·정렬값·학년·공개값·첨부 구조가 의도한 편집 외에 변경되지 않았는지 비교했다. 이 비교는 보존 로직의 검증이며 운영 자료 전체를 조회한 결과는 아니다.

`tsc --noEmit`, 변경 파일 ESLint, `next build --webpack`을 실행했다. 로컬 빌드에서는 네트워크 제한 때문에 Google Fonts 응답만 기존 로컬 폰트로 대체했다. 배포 소스에는 폰트 또는 빌드 설정 변경을 포함하지 않았다.

운영 교사 로그인 세션의 실제 Firestore 권한 및 실제 자료 저장은 이 테스트에서 확인하지 않았다. 배포 준비 상태 확인과 운영 로그인 환경의 기능 확인은 별개다.
