# 입금관리 세금 누적 집계 수정

## 원인

기존 형식의 수금 기록에는 수당금액과 수령액이 저장되어 있어도 `taxAmount`가 0일 수 있다. 입금관리 행은 `calculateFeeSettlement`로 세금을 미리 계산하지만, 누적 집계는 기존 기록의 `taxAmount`를 읽어 행의 세금과 누적 합계가 달라졌다.

## 변경

- 기존 기록의 수당금액과 수령액이 있고, 세금·보험료 합계가 모두 0이며, 두 금액의 차이가 기존 자동 계산 세금과 정확히 일치할 때만 공제 항목을 복원한다.
- 입금관리 API 응답에서 같은 정규화를 적용해 행과 누적 집계가 동일한 세금 데이터를 사용한다. 종합소득세 연동도 같은 정규화 함수를 사용한다.
- 조회 시 DB에 쓰지 않는다. 다시 조회해도 같은 결과가 나오며, 일반 저장 경로에서 정규화된 항목이 저장된다.
- 기존 세금·보험료 합계, 불일치하는 수령액, 미수령 기록은 자동 전환하지 않는다. 직접 지정한 0원 세금은 유지한다.
- 종합소득세 연동에서 기존 기록으로부터 자동 복원한 세금의 추정 표시를 유지한다.

## 검증

`node scripts/verify-fee-tax-totals.cjs` 통과:

- 예시 수당 720,000원, 수령액 696,240원의 차액은 23,760원.
- 기존 자동 산식: 소득세 `720,000 × 3 / 100 = 21,600`, 주민세 `720,000 × 3 / 1,000 = 2,160`, 합계 23,760원.
- 실제 입금관리 페이지의 집계 함수 실행 결과: 세금 누적 23,760원, 소득세 21,600원, 주민세 2,160원, 수령액 696,240원. 기존 합계로 중복 집계하지 않음.
- API 조회 → 저장 → 재조회 및 종합소득세 연동 일치.
- 기존 비영(非零) 세금·보험료 보존, 불일치 금액·미수령·공제 없는 기록 보존, 직접 입력한 0원 세금 보존.
- 조회 중 DB 쓰기 없음, 원본 객체 변경 없음, 정규화 반복 결과 동일.

타입 검사: `node node_modules/typescript/bin/tsc --noEmit` 통과.

전체 빌드: `node node_modules/next/dist/bin/next build --webpack` 통과. 로컬에서는 공유 의존성 심볼릭 링크가 Turbopack 파일 시스템 경계 밖으로 이어져 Webpack 빌드를 사용했다.

브라우저에서 운영 입금관리는 교사 로그인이 필요하여 실제 계정의 저장값과 화면은 검증하지 못했다. 위 검증은 격리된 회귀검증 데이터에 대한 결과이다.
