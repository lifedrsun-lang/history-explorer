# 보호자 수업방 서버 2차 작업 (운영 비활성)
- 별도 Firebase 컬렉션 guardian_school_configs, guardian_student_access, guardian_sessions, guardian_absence_notices, guardian_login_limits 사용.
- 운영 활성화 조건: GUARDIAN_CLASSROOM_ENABLED=true 및 GUARDIAN_TEACHER_UIDS(실제 담당 교사 UID 목록) 설정. 기본 비활성. 모든 guardian_* 컬렉션에 브라우저 직접 접근 거부 규칙 적용 및 기존 wildcard allow 규칙이 우회 허용하지 않는지 테스트. 실제 코드/데이터를 활성화하기 전에 수행.
- 학교/학생별 강한 무작위 코드 발급, 서버 해시 확인, 만료/회수 세션, 15분 단위 로그인 제한. 코드 원문은 최초 발급 응답에만 제공. 실제 교사 설정 UI 및 기존 학교 입장 분기는 후속.
- 실제 학생 레코드의 수강 상태/분기/학교/반 검증, 과제 존재 여부만 반환, 현재 동·은엽전만 반환. 학생 문서 전체 반환 금지.
- 실제 일정 소스가 확인되지 않아 교사 승인된 반별 12개 날짜를 설정하도록 작성. 과거 회차 출석 상태는 확인 전까지 미확인으로만 반환. 출석 데이터 연결은 미완료. 기존 출석부에 쓰지 않음.
- 확인한 등록 내용이 수정되면 확인 상태 초기화. 교사 확인은 변경 충돌 검사. 취소 시 문서 유지. 별도 출석부 수정 및 학교 제출 연동 없음.
- 주의: 권한은 단일 운영 교사 allowlist 기준으로 구현, 여러 교사 담당 학교별 권한 구분이 필요하면 활성화 전에 범위 검증 추가. Firestore 실제 규칙, TTL, 동시 요청 테스트, 빌드 미검증. 실제 저장 및 운영 활성화 금지.
