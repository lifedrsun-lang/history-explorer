# 보호자 수업방 1차 개발
- 격리된 화면: /student/guardian-preview. 예시 데이터만 사용, 실제 학생 정보나 데이터 저장 없음.
- 불참 사전등록 유효성 검증: 1~12회 중 예정 회차, 유형 및 사유 필수, 기타 직접 입력(공백 불가, 200자 제한), 수정 시 교사 확인 초기화.
- 실제 입장 화면은 app/student/StudentHistoryPage.tsx (기존 학생 입장 검증이 브라우저에서 이루어짐). 보호자 비밀번호 검증은 서버에서 처리해야 하며 학교 공통 코드만으로 학생 데이터 접근을 허용하지 않는다. 학생별 보호자 인증, 만료·회수 가능한 보호자 세션, 요청 제한, 서버 전용 데이터 접근 권한을 먼저 구현·검증할 것.
- 수강생 카드 연결 지점: app/teacher/components/StudentCard.tsx 의 StudentActivityBadges 다음 위치. 교사 권한은 기존 verifyTeacherRequest가 Firebase 로그인 여부만 확인하므로 민감한 사유 접근 전 교사 권한 및 담당 범위 검증 필요.
- 기존 실제 날짜와 출석 데이터 소스 확인 후 읽기 전용 연동. 준비물과 과제 상태 및 동/은엽전도 기존 데이터를 재사용. 실제 저장/설정/입장 분기/교사용 카드 연결은 이 변경에 포함되지 않는다.
- 기존 출석부 자동 변경, 학교 제출용 출석부 연동, 사진 업로드, 과제 상세 노출은 제외.
- 실제 운영 배포 금지: 인증·권한, 데이터 저장 규칙, 날짜/출석 소스 확인 및 빌드 테스트 후 검토.
