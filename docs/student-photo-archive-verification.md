## 공개를 막는 확인된 문제

읽기 전용 감사에서 기존 학생 데이터의 비인증 조회에 비밀번호 필드가 포함됨을 확인했다. 값·학생 ID는 보고서/로그에 출력하거나 파일에 저장하지 않았다. 기존 비밀번호를 서버에서 재확인하는 것만으로는 이 상태의 학생 본인 확인을 보장할 수 없다.

기존 로그인·계정 찾기·학생 관리 수정은 이번 지시의 보호 대상이다. 따라서 해당 기능은 수정하지 않았고 학생 사진 공개를 **기본 차단**했다. `PHOTO_ARCHIVE_ACCESS_REVIEWED`가 정확히 `true`인 경우에만 사진 API 학생 인증과 관리자 공개 저장이 가능하다. 이 값은 배포에 추가하지 않았다. 테스트 프로세스에서만 격리된 가짜 계정과 저장소에 대해 활성화했다.

**이 값을 테스트 편의로 켜면 안 된다.** 학생 원본 데이터/비밀번호의 비인증 노출 차단, 기존 조회·로그인·새로고침·과제·보상 흐름 보존, 타 계정 인증정보 노출 및 재사용 방지, 신뢰할 수 있는 서버 학생 인증을 별도 작업에서 보완하고 실제 배포에서 검증한 뒤 공개 차단을 해제해야 한다. 이 파일은 해당 보안 보완의 완료 증거가 아니다.

## 기존 데이터 확인과 권한 모델

- `lib/studentEnrollment.ts`: 실제 분기 이력은 `enrollmentTerms` (`YYYY-Qn`). 현재 수강 상태로 과거 분기를 추정하지 않는다.
- 실데이터의 분기 이력 존재는 읽기 전용으로 확인했다. 당시 학교·반을 기록한 분기별 이력은 조회되지 않았다. 현재 `grade`/`class`로 과거 반을 계산하지 않는다.
- 모든 학교의 실제 분기 종료일을 입증하는 공통 데이터는 확인하지 못했다. 앨범 생성 시 실제 종료일과 확인 근거를 필수 입력하며 날짜 기본값을 넣지 않는다.
- 관리자에게 실제 분기 이력이 있는 기존 계정만 후보로 보여 주며, **당시 학교·반 명부**로 학생을 직접 확인하도록 한다. 선택한 계정 키와 명부 근거를 새 앨범에 저장한다. 현재 학교 변경 학생도 관리자가 확인 후 지정할 수 있다.
- 서버는 목록·앨범 상세·사진 바이트 요청마다 명부의 정확한 학생 키 + 해당 연도/분기 이력 + 공개 여부 + 동의/명부 확인 + 공개기간을 모두 검사한다. 클라이언트가 보내는 학교·반은 권한 근거로 사용하지 않는다.
- 사진에 나온 학생 전원의 공개 동의 확인과 근거를 저장해야 공개할 수 있다. **사진 추가 시 DB 트리거가 같은 트랜잭션에서 공개와 기존 동의 확인을 해제**한다. 추가 사진 동의 확인 후 다시 공개해야 한다.

## 구현

- 학생 `StudentProfile`의 기존 책 내용 오른쪽에 사진 카드, 좁은 화면에서는 아래에 배치. 보상·학습·최근 활동 코드는 변경하지 않았다.
- 공개 중인 분기·종료일·D-day, 학생 전용 앨범 선택 화면.
- 사진 위치는 저장된 사진 순서/ID에 따른 결정적 비격자 배치. 선택 사진 중앙 이동/확대, 주변 사진 유지, 전환, 좌우/키보드, 터치로 장면 이동, 확대/축소, 전체 펼치기, 전체 화면, 움직임 줄이기 설정.
- 화면에 접근한 썸네일만 요청. 동시에 최대 네 사진 요청, 선택 사진 우선 처리. 선택 시 보기용 이미지로 전환. 화면을 닫으면 요청을 취소하고 임시 object URL을 해제.
- 관리자 `/teacher/photo-archive`, 방과후 관리에 진입 링크. 기존 Firebase 교사 비밀번호 로그인 경계를 사용하고 취소된 토큰과 학생/custom/anonymous 토큰을 거부한다. 앨범 소유 교사만 관리/원본 조회 가능하다.
- 학교·반·연도·분기는 생성 후 변경 불가. 제목·설명·분기 종료일·수동 공개 종료일·명부·동의·공개 여부는 버전 충돌 검사 후 수정.
- 여러 사진 업로드, 미리보기, 설명 수정, 삭제, 관리자 원본 다운로드. 기존 Supabase private bucket과 서버 클라이언트, Sharp를 재사용한다.
- 파일 한 장은 기존 bucket 한도인 10 MiB(10 × 1024 × 1024 bytes). 본문 제한을 피하기 위해 관리자 인증 후 파일 한 개의 경로에만 쓸 수 있는 signed **upload** URL을 발급한다. **학생용 signed download URL은 발급하지 않는다.**
- 실제 JPEG/PNG/WEBP 형식·픽셀 한도·비애니메이션 검사. 원본 bytes는 보존하고, 회전 보정 및 EXIF 제거한 썸네일/보기용 WebP 생성. 학생에게 저장 경로·원본은 반환하지 않는다.
- 모든 이미지 바이트는 인증된 POST API로 전달. 공개 링크/GET 이미지 URL 없음. `private, no-store`, same-origin 응답. 비공개 전환/만료 후 새 요청 차단. 저장소 I/O 후 다시 권한 검사.
- 자동 만료는 삭제 작업이 아니다. 삭제 버튼도 앨범에서 제외하는 soft delete로 원본 bytes를 보존한다. 이미 열람·저장한 사진 사본까지 회수하지는 못한다.
- MYBOX 후속 연동은 아래 2026-10-16 기록을 따른다. 최초 구현 시에는 사용하지 않았다.

## 공개기간 계산

1. 수동 공개 종료일이 없으면 학교의 입력된 실제 분기 종료일에 날짜 단위로 14일을 더한다.
2. 공개 종료일 다음 날 `00:00:00 Asia/Seoul`을 배타적 경계로 사용한다.
3. 서버 현재시각이 경계보다 작은 경우에만 열람한다. 종료일 `23:59:59.999` 허용, 다음 날 `00:00:00` 거부.
4. D-day는 한국시간 오늘 날짜와 공개 종료일의 날짜 차이다. 종료일 당일은 `D-day`.
5. 열린 학생 화면은 서버 기준 남은 시간에 맞춰 앨범을 닫으며, 수동 비공개/권한 변경은 화면 활성 중 30초 간격 재조회 시 반영한다. API의 새 사진 요청 차단은 즉시 적용된다.

## 2026-10-16 MYBOX 공유 폴더 가져오기

- 관리자 앨범에 `MYBOX 링크 확인 → 사진 선택 → 가져오기`를 추가했다. 공개 공유 폴더에서 원본을 다운로드하여 기존 비공개 보관·Sharp 썸네일/보기용 이미지 생성·학생 권한 API를 재사용한다.
- **실시간 동기화나 외부 링크 열기가 아닌 사본 가져오기**다. MYBOX의 추가·삭제·링크 만료가 저장된 사본에 자동 적용되지 않는다. 화면에 이를 안내하며 학생 공개 종료일은 기존 선랩 규칙을 따른다. MYBOX 설정은 변경하지 않았다.
- 네이버의 현재 공유 페이지 클라이언트 코드와 실제 비로그인 요청으로 `/service/v2/link/property`, `/service/link/folder/list`, `fs.mybox.naver.com/file/download.api`를 확인했다. 공개 개발자 API 계약은 확인되지 않았으므로 외부 웹 서비스 변경으로 호환성이 달라질 수 있다. 암호 폴더·다운로드 차단·중첩 폴더·500개 초과는 지원하지 않는다.
- 입력 주소 및 모든 단축 링크 리디렉션을 고정된 HTTPS 호스트/경로로 제한한다. 서버 인증과 앨범 소유권 확인 후에만 요청한다. 네이버 로그인 쿠키를 사용하지 않고 요청별 공유 세션만 유지한다. 공유 세션 쿠키는 응답에 포함하지 않으며 학생에게 원본 공유 주소를 반환하지 않는다.
- 항목은 매번 공유 폴더에서 다시 확인하고 다운로드 크기를 제한한다. 한 번에 한 장씩 처리하며 진행 상황·중지·부분 실패 재시도를 제공한다. 앨범 ID와 원본 바이트 해시로 동일 사진의 중복 등록을 방지하고 삭제된 항목을 다시 살리지 않는다.
- 기존 DB 트리거가 사진 추가 시 비공개/동의 미확인으로 변경한다. 학생 공개 차단 환경변수는 변경하지 않았다. 이 후속 작업에 추가 DB 마이그레이션은 없다.
