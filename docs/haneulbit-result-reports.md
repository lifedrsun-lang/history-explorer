# 하늘빛초 결과통지서 구현 및 검증 현황

## 구현

학교 관리 → 하늘빛초 화면 안의 `결과통지서` 카드 → `/teacher/after-school/haneulbit/reports`.

기존 `students` 컬렉션, `toStudentRosterRecord`, 학교 별칭 비교, 교사 Firebase 인증 API, Chromium/Puppeteer 및 기존 한글 폰트를 재사용한다. 학생 컬렉션에는 쓰지 않는다. 수강중 하늘빛초 학생만 기본 목록에 표시하고, 현재 학년·반·이름을 30초 간격 및 창 복귀 시 갱신한다. `schoolClass` 필드를 먼저 쓰고 기존 `className`/`class` 필드로 대체한다.

4개 항목의 5단계 평가를 같은 화면에서 라디오 버튼으로 입력한다. 항목별 전체 적용은 현재 수강생을 대상으로 하며, 개별 수정값을 덮어쓴다는 확인 메시지를 표시한다. 종합의견은 직접 입력하고 자동 생성하지 않는다. 문구 기능은 `ReportEvaluation.comment`에 선택 문구를 넣는 방식으로 추후 연결할 수 있으며 이번 작업에서는 임의 문구를 추가하지 않는다.

`haneulbit_result_reports/{year}-Q{quarter}`에 공통 정보와 revision을 저장하고, `evaluations/{studentId}`에 평가 및 출력 당시 학생 정보를 저장한다. 저장 요청은 변경된 행만 보낸다. 저장 트랜잭션에서 revision을 검사하여 다른 창의 변경사항을 덮어쓰지 않는다. 이전 분기 복사는 새 분기에 학습 활동 내용과 지도강사명만 복사하고 평가값은 복사하지 않는다.

현재 학생 정보가 변경되면 화면에 현재 값을 표시하고 저장된 출력 정보도 함께 보여준다. `현재 학생 정보 반영`으로 새 정보를 저장한 뒤 출력한다. 수강 종료·학생 삭제 이후에도 이미 저장된 기록은 보존되며 `과거 수강생 기록 함께 보기`로 열 수 있다.

작성완료 조건: 공통 교육기간·학습 활동·강사명, 학생 학년·반·이름, 네 평가와 직접 입력한 종합의견 모두 존재. 평가와 의견이 전혀 없으면 미작성, 그 외 필수값이 부족하면 작성중이다. 별도 미완료 필터는 미작성과 작성중을 포함한다.

PDF API는 저장된 revision의 자료만 출력한다. 출력 전 변경사항 저장이 필요하다. 개별 미리보기는 인증된 POST로 받은 PDF Blob을 dialog/iframe에서 표시한다. 전체 다운로드는 선택한 현재/과거 학생 중 작성완료 학생의 통지서를 하나의 PDF로 출력한다. 화면의 학생 순서대로 한 명당 A4 한 페이지를 배치하고, 파일명은 `하늘빛초_역사논술탐험_{연도}년{분기}분기_전체.pdf`이다. 학생별 다운로드와 미리보기는 기존대로 개별 PDF이다. BAND, 메일, 공유 연동은 추가하지 않았다.

## 원본 PDF 적용

첨부된 HWPX의 첫 번째 결과통지서를 XML 치수와 내장 미리보기로 대조하여 재현했다. 로고·안내문·12칸 활동 표·평가표·종합의견 영역·하단 안내문을 유지한다. 2026년 2분기까지는 기존 여름 안내문, 2026년 3분기부터는 새로 받은 가을 안내문과 수정된 표 치수를 사용한다. 각 양식의 분기 숫자는 자동 변경한다. 학교 원본 글꼴이 서버에 없어 기존 Noto Sans KR을 내장하며 글꼴 모양과 일부 줄바꿈에는 차이가 있다.

학습 활동은 원본의 12개 칸에 순서대로 배치한다. 긴 내용은 칸 사이로 이어지고 최소 11px에서도 영역을 넘으면 오류를 표시하여 내용 수정을 요구한다. 종합의견도 줄이지 않고 동일하게 검증한다. PDF 1페이지를 렌더링하여 원본 미리보기와 시각적으로 대조했다.

## 수행한 검증

- TypeScript 및 변경 파일 ESLint, 프로덕션 빌드.
- `node scripts/verify-haneulbit-reports.cjs`: 격리된 메모리 DB에서 수강생 필터·필드 매핑·상태·저장 재조회·revision 충돌·분기 보존·학생 변경/종료 후 과거 정보 보존·학생 컬렉션에 쓰기 없음.
- 실제 Chromium과 학교 템플릿으로 PDF 생성, 한글 추출, A4 1페이지, 4개 체크 및 5단계 전체의 체크 좌표를 HWPX 셀 좌표와 대조, 긴 의견과 활동의 영역 초과 거부.
- 인증된 PDF API의 inline 미리보기·attachment 개별 PDF·작성완료 학생만 포함하는 ZIP 응답 및 해제 검증. 비로그인 401, 저장 revision 불일치 409 검증.
- 운영 배포 READY와 sunlab.me.kr 연결 확인. 하늘빛초 카드 표시 및 실제 클릭 이동 확인.
- 운영 결과통지서 수강생 22명과 기존 수강생 관리 화면의 22명을 대조하여 전원의 이름·학년·반 일치 확인.
- 2026년 2분기에 원본 교육기간(2026-05-26~2026-08-14)만 저장. 학생 평가·의견·활동·강사명은 비워 둠. 저장 완료 메시지, 새로고침 후 저장된 2분기 재조회, 두 날짜 유지 확인. 새 3분기 화면을 열어도 2분기 데이터 유지 확인.
- 운영 화면에서 작성완료 0명 필터의 빈 목록, 미작성 22명 필터 확인. 학생의 실제 평가값 저장·운영 PDF 클릭 다운로드는 평가 내용이 제공되지 않아 시행하지 않았다. 아래에서 시험 검증과 운영 검증을 구분한다.

## 검증 범위

실제 학생의 평가 내용은 제공되지 않았으므로 검증 과정에서 임의 평가나 의견을 운영 DB에 확정 저장하지 않는다. 시험용 평가와 의견은 격리된 시험 저장소에서만 사용한다. 운영 학생 조회와 공통 정보 저장은 실제 화면에서 별도로 검증한다.

## 2026년 3분기 양식 변경 검증

신규 3분기 교육기간은 원본의 8월 18일~11월 6일로 기본 표시한다. 저장된 기간은 자동 변경하지 않는다. 격리 시험에서 새 가을 문구·교육기간·한글·A4 1장·5단계 전체 체크 좌표·12칸 활동 표 좌표·긴 의견 거부·미리보기/개별/ZIP API를 검증했다. 2분기를 다시 출력하면 이전 여름 안내문과 5월 26일~8월 14일 기간이 유지됨을 검증했다. 새 PDF를 PNG로 렌더링하여 새 HWPX 미리보기와 시각 대조했다.


## 주차별 활동 불러오기

2026년 3분기 공통 정보에 `주차별 활동 불러오기` 버튼을 추가했다. 기존 `HANEULBIT_SCHEDULE`의 수업 제목을 주차 순서대로 12줄로 불러온다. 1~4주차는 7호, 5~8주차는 8호, 9~12주차는 9호다. 다른 분기에는 해당 자료를 적용하지 않는다. 이미 입력된 내용이 있으면 직접 수정값까지 덮어쓴다고 확인하고, 취소 시 기존 입력을 유지한다. 불러오기만으로 DB에 저장하지 않으며 교사가 수정 후 기존 저장 버튼으로 해당 분기에 저장한다. 학생 평가값은 수정하지 않는다.

12줄 활동은 PDF 원본의 각 활동 칸에 하나씩 배치하고, 긴 제목은 해당 칸 안에서 글꼴 크기를 조정한다. 최소 크기에도 맞지 않으면 다음 주차로 밀어내지 않고 내용 수정 오류를 반환한다. 기존 자유 입력의 나머지 배치 방식은 유지한다.

검증: 전체 프로덕션 빌드, TypeScript, 변경 파일 ESLint 통과. `scripts/verify-haneulbit-activities-ui.cjs`에서 실제 React 화면과 Chromium으로 12개 제목 불러오기, 직접 수정, 덮어쓰기 취소/확인, 명시적 저장, 새로고침 재조회, 타 분기 비활성화, 과거 분기 보존, 평가 데이터 쓰기 없음 확인. `scripts/verify-haneulbit-reports.cjs`에서 주차 제목 저장·재조회 및 실제 PDF의 12개 원본 셀 좌표별 제목 일치, 긴 주차 제목의 영역 초과 거부, 기존 한글·체크·미리보기·PDF·ZIP 시험 통과. 시험 데이터는 격리된 인증/API/DB에서만 사용했다.

## 전체 통합 PDF 다운로드

`전체 통합 PDF 다운로드`는 ZIP 대신 하나의 PDF를 반환한다. 인증과 저장 revision 검사를 유지하고, 요청의 학생 순서대로 작성완료 기록만 한 번씩 출력한다. 각 학생의 활동·종합의견을 기존 방식으로 먼저 맞춘 뒤, 별도의 A4 페이지 안에 배치한다. 이전 분기도 해당 양식으로 출력한다. 새 PDF 병합 라이브러리나 외부 요청은 추가하지 않는다.

검증: 격리된 시험 자료 22명의 통합 PDF가 22페이지이며, 모든 페이지의 이름·개별 의견·체크 좌표·기호 폰트가 일치함을 확인했다. 2분기 통합 출력, API의 PDF 응답과 파일명, 요청 순서 유지, 미완료·중복·존재하지 않는 학생 제외, 개별 미리보기·다운로드와 revision 충돌을 검증한다. 위의 ZIP 검증 기록은 통합 PDF 변경 전 기능의 이력이다. 운영 학생 자료를 시험용으로 수정하지 않는다.

## 학교별 필수서류 및 제출 이력 연결

하늘빛초의 학교별 필수서류 관리에 저장된 결과통지서를 분기별로 표시한다. 결과통지서 화면에서 저장한 뒤 `제출완료 표시`를 누르면 밴드에 직접 제출했다는 확인을 거쳐 저장 revision·학생 ID·제출일·담당자 정보를 기록한다. 같은 저장본을 재시도해도 제출 이력이 중복되지 않는다. 결과통지서의 완료 표시, 기존 학교별 제출 이력, 최근 처리 상태는 하나의 Firestore 트랜잭션으로 반영한다. 실제 밴드 전송은 수행하지 않는다.

생성된 서류 목록의 링크는 해당 연도·분기의 결과통지서를 연다. 저장과 제출 시 같은 브라우저의 학교 관리 탭에 갱신을 알리고, 갱신 중 입력하던 담당자 초안은 유지한다. 제출 후 수정·저장하면 기존 제출 이력은 보존하고 현재 분기는 재제출 필요로 표시한다.

검증: `scripts/verify-haneulbit-submissions.cjs`에서 격리 DB의 인증·필수 항목·revision 충돌·중복 및 동시 요청·제출/수정/재제출·과거 분기·학교 및 교사별 이력 분리·학생 컬렉션 변경 없음 검사. `scripts/verify-haneulbit-submissions-ui.cjs`에서 실제 React/Chromium/API로 확인 취소, 제출 버튼 상태, 학교 목록과 밴드 제출 이력의 탭 간 갱신, 담당자 초안 유지, 수정 후 재제출, 새로고침 유지 검증. 실제 학생의 제출완료 상태는 시험으로 변경하지 않는다.
