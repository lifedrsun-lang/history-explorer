# 하늘빛초 결과통지서 구현 및 검증 현황

## 구현

학교 관리 → 하늘빛초 화면 안의 `결과통지서` 카드 → `/teacher/after-school/haneulbit/reports`.

기존 `students` 컬렉션, `toStudentRosterRecord`, 학교 별칭 비교, 교사 Firebase 인증 API, Chromium/Puppeteer 및 기존 한글 폰트를 재사용한다. 학생 컬렉션에는 쓰지 않는다. 수강중 하늘빛초 학생만 기본 목록에 표시하고, 현재 학년·반·이름을 30초 간격 및 창 복귀 시 갱신한다. `schoolClass` 필드를 먼저 쓰고 기존 `className`/`class` 필드로 대체한다.

4개 항목의 5단계 평가를 같은 화면에서 라디오 버튼으로 입력한다. 항목별 전체 적용은 현재 수강생을 대상으로 하며, 개별 수정값을 덮어쓴다는 확인 메시지를 표시한다. 종합의견은 직접 입력하고 자동 생성하지 않는다. 문구 기능은 `ReportEvaluation.comment`에 선택 문구를 넣는 방식으로 추후 연결할 수 있으며 이번 작업에서는 임의 문구를 추가하지 않는다.

`haneulbit_result_reports/{year}-Q{quarter}`에 공통 정보와 revision을 저장하고, `evaluations/{studentId}`에 평가 및 출력 당시 학생 정보를 저장한다. 저장 요청은 변경된 행만 보낸다. 저장 트랜잭션에서 revision을 검사하여 다른 창의 변경사항을 덮어쓰지 않는다. 이전 분기 복사는 새 분기에 학습 활동 내용과 지도강사명만 복사하고 평가값은 복사하지 않는다.

현재 학생 정보가 변경되면 화면에 현재 값을 표시하고 저장된 출력 정보도 함께 보여준다. `현재 학생 정보 반영`으로 새 정보를 저장한 뒤 출력한다. 수강 종료·학생 삭제 이후에도 이미 저장된 기록은 보존되며 `과거 수강생 기록 함께 보기`로 열 수 있다.

작성완료 조건: 공통 교육기간·학습 활동·강사명, 학생 학년·반·이름, 네 평가와 직접 입력한 종합의견 모두 존재. 평가와 의견이 전혀 없으면 미작성, 그 외 필수값이 부족하면 작성중이다. 별도 미완료 필터는 미작성과 작성중을 포함한다.

PDF API는 저장된 revision의 자료만 출력한다. 출력 전 변경사항 저장이 필요하다. 개별 미리보기는 인증된 POST로 받은 PDF Blob을 dialog/iframe에서 표시한다. 전체 다운로드는 선택한 현재/과거 학생 중 작성완료 학생의 PDF를 UTF-8 ZIP으로 묶는다. 동명이인 파일명 충돌은 학년·반과 순번을 추가해 해결한다. BAND, 메일, 공유 연동은 추가하지 않았다.

## 원본 PDF 적용

첨부된 HWPX의 첫 번째 결과통지서를 XML 치수와 내장 미리보기로 대조하여 재현했다. 로고·안내문·12칸 활동 표·평가표·종합의견 영역·하단 안내문을 유지한다. 안내문은 사용자의 선택대로 분기 숫자만 자동 변경한다. 학교 원본 글꼴이 서버에 없어 기존 Noto Sans KR을 내장하며 글꼴 모양과 일부 줄바꿈에는 차이가 있다.

학습 활동은 원본의 12개 칸에 순서대로 배치한다. 긴 내용은 칸 사이로 이어지고 최소 11px에서도 영역을 넘으면 오류를 표시하여 내용 수정을 요구한다. 종합의견도 줄이지 않고 동일하게 검증한다. PDF 1페이지를 렌더링하여 원본 미리보기와 시각적으로 대조했다.

## 수행한 검증

- TypeScript 및 변경 파일 ESLint, 프로덕션 빌드.
- `node scripts/verify-haneulbit-reports.cjs`: 격리된 메모리 DB에서 수강생 필터·필드 매핑·상태·저장 재조회·revision 충돌·분기 보존·학생 변경/종료 후 과거 정보 보존·학생 컬렉션에 쓰기 없음.
- 실제 Chromium과 학교 템플릿으로 PDF 생성, 한글 추출, A4 1페이지, 4개 체크 및 5단계 전체의 체크 좌표를 HWPX 셀 좌표와 대조, 긴 의견과 활동의 영역 초과 거부.
- 인증된 PDF API의 inline 미리보기·attachment 개별 PDF·작성완료 학생만 포함하는 ZIP 응답 및 해제 검증. 비로그인 401, 저장 revision 불일치 409 검증.
- 운영 배포 READY와 sunlab.me.kr 연결 확인. 하늘빛초 카드 표시 및 실제 클릭 이동 확인.
- 운영 결과통지서 수강생 22명과 기존 수강생 관리 화면의 22명을 대조하여 전원의 이름·학년·반 일치 확인.
- 2026년 2분기에 원본 교육기간(2026-05-26~2026-08-14)만 저장. 학생 평가·의견·활동·강사명은 비워 둠. 저장 완료 메시지, 새로고침 후 저장된 2분기 재조회, 두 날짜 유지 확인. 새 3분기 화면을 열어도 2분기 데이터 유지 확인.
- 운영 화면에서 작성완료 0명 필터의 빈 목록, 미작성 22명 필터 확인. 학생의 실제 평가값 저장·운영 PDF 클릭 다운로드는 평가 내용이 제공되지 않아 시행하지 않았다. 아래에서 시험 검증과 운영 검증을 구분한다.

## 검증 범위

실제 학생의 평가 내용은 제공되지 않았으므로 검증 과정에서 임의 평가나 의견을 운영 DB에 확정 저장하지 않는다. 시험용 평가와 의견은 격리된 시험 저장소에서만 사용한다. 운영 학생 조회와 공통 정보 저장은 실제 화면에서 별도로 검증한다.

## 요청된 14개 항목의 근거

| 항목 | 결과와 범위 |
|---|---|
| 1. 카드 표시 | 운영 하늘빛초 화면에서 확인 |
| 2. 카드 이동 | 운영에서 클릭하여 결과통지서 경로 이동 확인 |
| 3. 실제 수강생 | 운영 22명 자동 표시 확인 |
| 4. 학년·반·이름 | 기존 수강생 관리의 22명 전원 대조 일치 |
| 5. 저장·새로고침 | 운영 공통 교육기간 저장·새로고침 후 재조회 유지; 평가값은 격리 시험 DB에서 저장·재조회 검증 |
| 6. 상태 | 운영 미작성 22명과 완료 0명 필터 확인; 작성중/완료 필수값 로직은 시험 검증 |
| 7. 미리보기 | 인증된 PDF API가 inline PDF 반환함을 실제 Chromium 시험 검증; 운영 학생 미리보기 클릭은 미실행 |
| 8. 원본 양식 | HWPX XML 치수와 내장 미리보기를 출력 PNG와 시각 대조. 기존 한글 폰트로 대체하여 글꼴은 일부 차이 |
| 9. 한글 | 실제 PDF 텍스트 추출 및 시각 검증 |
| 10. 평가 체크 | 5단계 전체의 체크 4개가 각 원본 행·열 좌표 안에 위치함을 PDF 좌표 검사 |
| 11. 의견 영역 | 실제 렌더러의 긴 의견 거부 검증, 출력 영역 시각 검사 |
| 12. 개별 PDF | 인증된 API의 attachment·파일명·PDF 데이터 시험 검증; 운영 학생 클릭 다운로드는 미실행 |
| 13. 전체 다운로드 | 작성완료 학생만 포함한 실제 PDF ZIP 응답·해제·한글 파일명 시험 검증; 운영 학생 클릭 다운로드는 미실행 |
| 14. 이전 분기 보존 | 운영 2분기 저장 후 새 3분기·새로고침·2분기 재조회 유지; 시험 DB에서 복수 분기 평가 보존 검증 |
